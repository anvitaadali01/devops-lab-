# Jenkins CI Automation

This self-contained exercise demonstrates a basic Continuous Integration (CI) workflow with Jenkins. Jenkins runs in Docker; a small Python application is checked out from GitHub, its dependencies are installed, and automated tests run on each pipeline build. 

## What the pipeline does

1. Checks out the repository source.
2. Creates a Python virtual environment and installs `requirements.txt`.
3. Runs the `pytest` test suite and publishes a JUnit test report in Jenkins.
4. Marks the build successful or failed and prints a clear message.

## Prerequisites

- Windows 10/11 with Docker Desktop installed and running with Linux containers enabled.
- GitHub access to the repository containing this folder.
- No separate Jenkins or Python installation is needed on Windows. The Jenkins image includes Python for the sample build.

> The Jenkins container and volume are for this local exercise. Do not expose this Jenkins instance to the public internet.

## 1. Start Jenkins (Windows PowerShell)

Open PowerShell in this folder (the folder containing `docker-compose.yml`) and run:

```powershell
docker compose up -d --build
```

The first run downloads/builds the Jenkins image and may take several minutes. Check that the container is running:

```powershell
docker compose ps
```

Expected: the `jenkins` service shows `Up` and port `8080` is published. Jenkins may need another minute to finish starting. To watch startup messages, run `docker compose logs -f jenkins`; press **Ctrl+C** after Jenkins reports that it is ready. This stops viewing logs, not Jenkins.

## 2. Unlock Jenkins and finish first-time setup

1. Open [http://localhost:8080](http://localhost:8080) in a browser.
2. In PowerShell, retrieve the generated initial administrator password:

   ```powershell
   docker exec jenkins-ci-automation cat /var/jenkins_home/secrets/initialAdminPassword
   ```

3. Copy the password printed in your own terminal into the **Administrator password** page. The password is generated by Jenkins; this project contains no real or default credentials.
4. Select **Install suggested plugins** and wait for installation to finish. Confirm that **Pipeline**, **Git**, and **JUnit** plugins are installed (install any missing ones from **Manage Jenkins > Plugins**).
5. Create your own Jenkins administrator account when prompted, then continue to the Jenkins dashboard.

## 3. Create and configure the pipeline

In Jenkins:

1. Select **New Item**, enter a name such as `devops-lab-jenkins-ci`, choose **Pipeline**, and select **OK**.
2. In the job configuration, find **Pipeline** and set **Definition** to **Pipeline script from SCM**.
3. Set **SCM** to **Git** and enter this repository URL:

   ```text
   https://github.com/anvitaadali01/devops-lab-.git
   ```

4. Set **Branch Specifier** to `*/main`.
5. Set **Script Path** to `jenkins-ci-automation/Jenkinsfile` (the Jenkinsfile is in this exercise subfolder, not at repository root).
6. Select **Save**, then select **Build Now**.

The repository is public, so no GitHub credentials are needed. Do not add passwords or tokens to the Jenkinsfile or this folder. If the repository is private, configure credentials in Jenkins' credential store instead of putting a secret in source code.

## 4. Verify the CI result

Open the build number in **Build History**, then open **Console Output**. A successful run shows the checkout, dependency installation, and test stages, followed by a message similar to:

```text
3 passed
CI passed: dependencies installed and all tests passed.
Finished: SUCCESS
```

The build page also provides a **Test Result** report. A failed test or failed pipeline stage makes the build result **FAILURE** and prints the failure message/logs in Console Output. Fix the issue and select **Build Now** again.

## Optional: run the sample tests on Windows

This is optional; Jenkins performs the tests inside its container. From this folder, PowerShell can run the tests locally if Python is already installed:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Expected: `3 passed`.

## Stop or reset Jenkins

From this folder in PowerShell, stop Jenkins while preserving its configuration and build history:

```powershell
docker compose down
```

Start it again later with `docker compose up -d`. To permanently remove this exercise's Jenkins data as well, use `docker compose down --volumes`; this deletes the Jenkins configuration, jobs, and build history stored in the named volume.

## Files

- `Jenkinsfile` — declarative Jenkins pipeline.
- `Dockerfile` and `docker-compose.yml` — Jenkins container setup, persistent data, and local ports.
- `app.py` — sample application.
- `tests/test_app.py` — automated tests.
- `requirements.txt` — Python test dependency.
